# 微信小程序版扫雷 · 规格说明与与 Windows 经典版差异

本文档面向将现有原生 HTML/JS 逻辑移植到微信小程序（WeApp），在不改变核心玩法的前提下，梳理要实现的功能、配置项、交互映射、胜负判定与工程化细节，并明确与 Windows 经典扫雷的差异点。实现以当前 `original/mine.html` 的数据与算法为主线，尽量在其上扩展与完善。

## 项目目标
- 保留经典扫雷的核心乐趣（翻格、标旗、快速开、胜负判定、计时）。
- 适配移动端交互（点击/长按/双击或双指），保证首击体验与可玩性。
- 提供灵活的尺寸与难度配置，便于后续扩展与活动玩法。
- 代码结构贴合现有逻辑，便于对照与验证；必要时做小幅修正以符合规则。

## 术语与数据表示（沿用现有实现）
- 棋盘 `board[r][c]` 的取值：
  - `E`：未翻开的空格（Empty）
  - `M`：未翻开的地雷（Mine）
  - `B`：已翻开的空白（Blank，周围 8 格无雷）
  - `1`–`8`：已翻开的数字格
  - `X`：踩雷后显示的爆炸格（Game Over）
- 标记 `flags[r][c]` 的取值：
  - `' '`：无标记
  - `'P'`：插旗（🚩）
  - `'?'`：问号（❓，可选）

## 棋盘与布雷
- 尺寸：默认 `20 × 20`，支持自由配置 `width × height`。
- 布雷方式：
  - 概率布雷：示例中 `Math.random() < p`（如 `p = 0.2`）。实际雷数在期望附近波动；生成后可统计总雷数用于 UI 显示。
- 首击保护（强烈推荐开启）：
  - 首次点击之前不布雷；在首击后生成雷区，并避开首击格及其 8 邻域。

## 操作与手势映射（移动端）
- 单击（tap）：翻开一个未翻格。
  - 若为 `M`：失败，显示 `X` 并结束。
  - 若周围无雷：显示 `B`，并自动向外扩散直至边缘数字。
  - 若周围有雷：显示数字 `1–8`。
- 长按（long press）：在未翻格上循环标记：空白 → 🚩 → ❓ → 空白。可通过设置关闭问号阶段。
- 快速开（quick open / chord）：
  - Windows 为中键或左右键同时；小程序建议用“数字格双击”或“数字格双指轻点”。
  - 触发条件：点击一个已翻开的数字格，若其 8 邻域中旗帜（🚩）数量等于该数字，则自动翻开其余邻格。
  - 风险：若未旗帜覆盖的邻格存在雷，则立即失败。

## 胜负与计时/计数
- 失败：
  - 翻开雷格，或在快速开时误开未标记的雷。
  - 失败后可选择：显示所有雷；用特殊标记标出错旗（Windows 会显示错旗）。
- 胜利：
  - 所有非雷格均被翻开（无需全部插旗）。
- 计时：
  - 在第一次成功翻开非雷格时启动计时；在胜利或失败时停止。
- 剩余雷数显示：
  - 若为固定雷数：`remaining = 总雷数 - 旗帜数`。
  - 若为概率布雷：生成后可统计真实总雷数，再按上述方式显示。

## 可配置项
- 交互：
  - 快速开触发方式（双击 / 双指轻点）。
  - 长按时长阈值。
  - 是否启用问号状态。
- 首击保护：开/关；是否启用“首击空白”。
- 视觉与动画：数字颜色、翻开/插旗动画、触感反馈等。

## 逻辑流程（与现有代码对齐并完善）
1) 新局初始化：
   - 清空 `board` 为 `E`、清空 `flags`。
   - 计时器清零；状态设为 `idle`。
2) 首击：
   - 开启首击保护：首击时再布雷，并避开首击及其 8 邻域；可选“首击空白”。
3) 翻开单格（tap）：
   - 已插旗（🚩）的格子不可被翻开。
   - 命中 `M` → 置 `X`，失败。
   - 非雷：计算周围 `M` 数量，`0` 则置 `B` 并递归扩散；否则置 `1–8`。
4) 标记（long press）：
   - 循环空白 → 🚩 → ❓ → 空白；插旗格不响应翻开。
5) 快速开（双击/双指）：
   - 仅对数字格生效；若 8 邻域旗帜数等于该数字，则尝试翻开其余邻格：
     - 对每个未翻且未插旗邻格：若是 `M` → 失败；若是 `E` → 按步骤 3 翻开。
6) 胜负检查：
   - 每次成功翻开后检查是否已经没有未翻开的非雷格，若是则胜利。

## UI 结构（小程序）
- 页面结构：
  - `pages/index/index`（或 `pages/game/game`）：棋盘区域 + 顶部状态栏（计时、剩余雷数、重开）。
- 组件化（可选）：
  - `Board` 组件（网格渲染，接收 `board`、`flags`）。
  - `Cell` 组件（单元格渲染与交互）。
- 渲染优化：
  - 避免频繁 setData 大对象，按行/块更新；或使用 `virtual-list` 思路（大盘面时）。

## 状态与数据结构
- 全局/页面状态：
  - `board: string[][]`、`flags: string[][]`
  - `width, height, minesCount`
  - `firstClickDone: boolean`
  - `timer: { running, startAt, elapsed }`
  - `gameState: 'idle' | 'playing' | 'won' | 'lost'`
- Cell 级对象（可选重构）：
  - `{ isMine, revealed, flagged, questioned, number }`

## 与现有 HTML/JS 的映射与改进建议
- 保持核心函数：
  - `updateBoard(board, [r,c])`：处理一次翻开。
  - `revealAdjacent(board, [r,c])`（现名 `revealAjacent`）：递归扩散。
  - `countMines(board,[r,c])`：统计周围雷数。
  - `countFlags(flags,[r,c])`：统计周围旗帜数。
- 必要修正（不改变玩法，仅与规则对齐）：
  - `countFlags` 仅统计 `'P'`（🚩），不应计入所有邻格。
  - 快速开逻辑：仅对数字格触发；邻域遍历使用 `row/col` 而非中心 `r/c`；若遇到未插旗的 `M` 应判负。
  - 翻开时跳过插旗格（🚩不可左击）。
  - 递归扩散时同样跳过插旗格，防止误开。
  - 读取 `dataset.num` 前先判断元素是否为数字格，避免 `undefined`。
- 首击保护：
  - 将布雷延迟到首击后，根据首击坐标生成雷区并避开 9 宫格。

## 配置与难度预设
- 固定只有一个难度

## 失败/胜利后的表现
- 失败：
  - 展示所有雷；保留已插旗；对错旗标红或加叉；禁用进一步操作。
- 胜利：
  - 停止计时；可自动为剩余未翻格插旗（可选）；展示祝贺动画。

## 计时与统计
- 计时：首个成功翻开后开始；结束时停止。
- 统计：只统计当次游戏用时，其他不考虑。

## 测试清单（建议）
- 首击不踩雷；启用/关闭首击保护时的差异。
- 快速开：旗帜数等于数字时正确展开；存在未插旗雷时失败。
- 递归扩散：空白区域正确连通，数字边界正确停止。
- 标记循环：空白 → 🚩 → ❓ → 空白；问号开关生效。
- 插旗格不可左击；移除旗后可正常翻开。
- 胜利判定：仅当所有非雷格揭示时触发。
- 失败表现：显示雷与错旗；禁止继续交互。
- 计时起止：首次成功翻开开始；结束时停止。
- 大盘面性能：滚动与点击不卡顿；setData 量可控。
