# Executing Plans — ProjectShelf 项目适配版

本技能是项目维护的独立适配版，借鉴 [obra/superpowers executing-plans](https://github.com/obra/superpowers/tree/main/skills/executing-plans) 的逐项执行、验证和进度记录方法，不是上游原版，也不依赖其脚本、工作区或配套技能。

## 执行入口

先读取根 AGENTS.md、docs/ARCHITECTURE.md 及用户指定功能的权威方案。按涉及领域读取后端、前端与测试文档，不一次加载无关资料。

确认用户要求执行的阶段、验收目标和现有授权。仅要求写方案、评审或查询时不开始实现。安装或调用技能本身不授权提交、推送、部署、改写历史或删除用户数据。

检查工作区状态及相关差异，区分既有改动与本任务改动。默认当前 Agent 在当前工作区逐项完成；不强制创建 worktree，不自动派发子代理，不安装其他技能。用户明确要求隔离或委派时，按实际可用工具及项目规则执行。

## 准备可执行任务

如果方案只有架构或宽泛阶段，先使用 [writing-plans](../writing-plans/SKILL.md) 在同一权威文档内补齐实施清单，不为同一功能新建日期版计划。

每个任务至少明确：目的、相关文件、输入输出或共享接口、前置任务、可观察的验收行为和验证方式。按依赖顺序执行；相关实现与必要测试、契约及迁移保持完整，不仅按文件类型拆任务。

开始前核对任务间接口、依赖版本、执行命令和方案与当前代码的差异。遵循用户要求与项目架构；计划中的过时细节不能覆盖它们。能在已授权范围内解决的常规问题自行处理，并记录理由；影响产品行为、阶段范围或技术选型的未决问题先取得澄清，继续其他不受影响的工作。

## 逐项执行

1. 读取当前任务的实际说明及相关代码，不仅依赖对话摘要；在权威文档标记进行中。
2. 对业务行为使用 [tdd](../tdd/SKILL.md)：先验证失败行为，再实现并验证通过。不要为纯文档、低影响可逆配置或实现细节机械添加测试；选择与风险相符的检查。
3. 完成满足任务的最小完整改动，按需应用已安装的 React 或 Playwright 技能，不提前实现后续阶段。
4. 运行任务要求的验证，读取真实输出与退出码。失败时定位原因并修复；不靠删除有效断言、降低校验或绕过 hook 取得通过。
5. 使用 [verification-before-completion](../verification-before-completion/SKILL.md) 核对完成证据。没有真实验证结果时不勾选完成，记录失败或环境阻碍。
6. 更新任务状态、验证证据及必要决定，再进入下一项。用户已授权整个阶段时连续推进，不逐项重复询问是否继续。

测试失败时区分代码缺陷、测试缺陷、计划错误和外部环境问题。修正规划要同步修改文档及受影响任务，不能静默偏离。涉及不可逆操作、凭据、用户数据或超出授权的外部变更时，遵守原有授权边界，不把连续执行理解为额外许可。

## 进度与恢复

在功能权威文档维护简洁记录，不另建永久 ledger、重复方案或依赖私有 Agent 状态。记录任务状态、实际变更、验证命令与结果摘要、未解决事项、以及偏离原计划的决定和理由。不要保存凭据、完整控制台输出或无价值的操作流水。

恢复执行时重读记录，检查相关文件、Git 差异与已有提交；以实际状态和证据判断下一项，不重复已完成工作，也不把历史通过结果当作新改动的验证。必要临时产物在结束后清理，只处理本任务创建且已确认可删除的文件。

## 整体验收与交付

逐条核对方案验收条件并自查整体差异，特别检查并发、权限、事务、错误路径和跨任务接口。需要真实数据库、Redis 或容器的行为用相应环境验证，不能把替身测试等同于真实集成验证。

按增量运行项目要求的格式、类型、构建和测试检查；有阻碍时如实报告未验证项，不宣称阶段完成。独立审查仅在用户要求或实际适用的项目流程授权时使用，不自动调度审查子代理。

用户已授权提交时使用 [atomic-commits](../atomic-commits/SKILL.md) 按目的拆批并检查暂存差异；否则保留未提交改动。禁止通过计划中的“提交”步骤推导用户已授权，不自动推送。

交付时说明完成的阶段、关键行为变化、实际验证结果、剩余限制和提交状态。同步权威文档，使方案、实施清单和验收记录与最终实现一致。
